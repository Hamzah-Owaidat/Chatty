# design-sync notes for Chatty

- **No component-library build.** Chatty is a private Next.js app (`package.json` has no `main`/`module`/`exports`, no `dist/`). This sync runs in synth-entry mode (scans `src/` directly). `--entry ./dist/index.js` is passed on every build/resync run purely so the converter's PKG_DIR-resolution walk finds the repo's real `package.json` (it doesn't exist as a file - that's expected and intentional, see `[NO_DIST]` lines in the build log).
- **cssEntry is a Next.js build artifact, not a stable path.** `src/app/globals.css` uses Tailwind v4's `@import 'tailwindcss'`, which esbuild can't process directly. `cfg.cssEntry` points at the compiled CSS Next.js emits to `.next/static/css/<hash>.css` - **that hash changes on every `next build`**. Before any re-sync: run `npm run build` (ignore the ESLint failure at the end - the CSS/compile step that matters already succeeded by then), find the new hash via `ls .next/static/css/`, and update `cfg.cssEntry` in `.design-sync/config.json` to match before running the converter.
- **`src/app` is excluded from sync scope.** Route files (`page.tsx`, `layout.tsx`, etc.) aren't composable design-system components, and `src/app/layout.tsx` side-effect-imports the raw (uncompiled) Tailwind CSS, which crashes the synth-entry JS bundle. `componentSrcMap` exclusions only filter the catalog, not the underlying bundle entry file, so a forked `.design-sync/overrides/source-kit.mjs` drops `src/app/**` from discovery entirely (declared in `cfg.libOverrides`). On a fresh clone, recreate the symlink the fork needs to resolve its `ts-morph` import: `ln -sfn ../.ds-sync/node_modules .design-sync/node_modules`.
- **Scope**: `src/components`, `src/layout`, `src/icons` only (user explicitly chose to try including `src/app` first; it hit exactly the predicted Next.js-convention wall on the first attempt and was dropped).
- **Preview-authoring scope for the first sync**: floor cards for everything (no hand-authored previews yet). Richer previews can be authored incrementally on any later re-sync.

- **Default-exported components need an explicit re-export.** The synth entry uses `export *`, which skips default exports. The forked `source-kit.mjs` adds `export { default as <Name> }` for each default-exported component. Without it, 59 of 73 components are missing from `window.Chatty`.
- **Next.js env vars need a shim.** Components read `process.env.NEXT_PUBLIC_*` at module load. Next normally inlines these at build time, but this bundle does not, so the bundle throws on load. `.design-sync/shims/process-shim.mjs` defines `process` and is wired in through `cfg.extraEntries`.
- **Authored previews** (`.design-sync/previews/`): Badge, Checkbox, and DropdownItem were blank as floor cards, so they have hand-written previews. The other 70 components are floor cards.
- **StatusPage deferred (user decision).** Its call-to-action uses `bg-primary`, `text-primary`, and `text-muted-foreground`, which this project never defines, so the button renders invisible. The live 404/500 pages have the same bug. It ships as a floor card until the component's classes are fixed (map them to `bg-brand-500`, `text-brand-500`, `text-gray-500`), then re-author and re-grade.
- **Outfit font, accepted as-is.** `globals.css` declares `--font-outfit`, but the app never loads the font file or a Google Fonts link. The live site renders in the system sans-serif, and so do designs. This is recorded as an accepted substitute (user approved).
- **`[TOKENS_MISSING]` is expected.** `globals.css` sets `--font-*: initial`, so `--font-sans` and `--font-mono` are not defined in the app either.
- **`menu-item`, `menu-item-*`, and `menu-dropdown-item` are missing from the compiled CSS.** They are used in `src` (AppSidebar) but do not appear in the Next.js build output, so the live app may be unstyled there too. This is an app-side issue to investigate, not a converter issue.
- **Playwright + Chromium** are installed in `.ds-sync/` for the render check.

## Re-sync risks
- The `.next/static/css/<hash>.css` cssEntry path WILL go stale the moment anyone runs `npm run build` again for any reason - it's not committed, not stable, and nothing enforces keeping `.design-sync/config.json` in sync with it. Always regenerate + re-point before a re-sync, or the build will fail on a missing file (or silently ship stale styles if a stale hash happens to still exist on disk).
- Many of Chatty's components (especially anything outside `src/components/ui`/`src/components/form`) are wired into Redux state, SignalR real-time connections, and auth/JWT context. These will very likely need `cfg.provider` wrapping and/or render-check triage (`[RENDER]` context errors) during the self-heal loop - expect this, it's not a sign something is broken.
- `src/layout` (AppHeader, AppSidebar, Backdrop) may also assume things about routing/auth context that aren't satisfied in an isolated preview - same triage path as above.
